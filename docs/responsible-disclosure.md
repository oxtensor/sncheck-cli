# Responsible Disclosure

SNCheck surfaces risk signals in third-party subnet repositories. When you find a
severe issue using SNCheck, disclose it responsibly.

## Workflow

1. The researcher finds a severe issue in a subnet repo.
2. The researcher reports it privately to the subnet maintainers and the SNCheck
   maintainers — not in a public issue.
3. Maintainers confirm and coordinate a fix.
4. A public SNCheck rule or report can be published after the fix, or after a
   reasonable disclosure window.

## Default disclosure windows

- **7 days** for critical active key-theft risk.
- **30 days** for high severity issues.
- **90 days** for medium and lower severity issues.

Adjust based on severity and exploitability.

## Wording

Report risks, not accusations. Use neutral, evidence-first language. Avoid terms
like "scam", "thief", or "malicious owner". See also [SECURITY.md](../SECURITY.md).
